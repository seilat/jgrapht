1. Eppstein’s k-shortest paths

Eppstein’s algorithm (EppsteinKShortestPath, EppsteinShortestPathIterator) enumerates the $k$ shortest paths from $s$ to $t$ in $O(m + n \log n + k \log k)$ time. The idea: build the shortest-path tree $T$ rooted at $t$ on the edge-reversed graph; any $s\!\to\!t$ path in the original graph can be written as the unique tree path plus a set of sidetracks — non-tree edges that, when taken, force you off the tree-path and back through $T$. The cost of a sidetrack $e=(u,v)$ is $\delta(e) = w(e) + d_T(v) - d_T(u) \ge 0$.

Eppstein expands a min-heap keyed by total sidetrack cost δ(e1)+δ(e2)+… The 1st path uses no sidetracks (the tree-path); subsequent paths add the cheapest combinations.

See: EppsteinKShortestPath, EppsteinShortestPathIterator. Reference: Eppstein, D. (1999). “Finding the k Shortest Paths”. SIAM J. Comput. 28(2), 652–673.

2. Yen with A* — bounded-pruned k-shortest paths

BoundedPrunedYenKShortestPath (PR #1338) returns the same ordered path-weight sequence as YenKShortestPath but defers each Yen spur task behind an admissible lower bound. Reverse distances from the sink, computed once on the original graph, stay valid under any later edge/vertex bans (removing edges can only increase shortest-path distance), so: 

lowerBound(spur task) = rootCost  +  h(spurNode)   where  h(v) = d(v, sink)
                                                      on the original graph

If every still-deferred task has   lowerBound ≥ cheapest materialized candidate,
the candidate is provably the next k-th shortest path.
The A* spur engine (AStarSpurEngine) plugs h(v) into AStarShortestPath on a MaskSubgraph view that hides the banned vertices/edges — no shortest-path logic is duplicated.

See: BoundedPrunedYenKShortestPath, AStarSpurEngine, DijkstraSpurEngine, SpurShortestPathEngine. Measured 10.9× (n=500) and 27.3× (n=1500) faster than YenKShortestPath on Gn,p random digraphs (A* engine).

3. Dijkstra many-to-many, one source

DijkstraManyToManyShortestPaths.getPaths(V) (PR #1340) overrides the base-class fallback that re-runs Dijkstra from the same source once per target. A single DijkstraClosestFirstIterator from $s$ produces the full shortest-path tree to every reachable vertex in one pass.

The base-class fallback is preserved for DefaultManyToManyShortestPaths (would otherwise bypass the user-supplied algorithm function) and CHManyToManyShortestPaths (would otherwise bypass its contraction-hierarchy preprocessing).

See: DijkstraManyToManyShortestPaths.

4. AllDirectedPaths, non-simple mode

AllDirectedPaths (PR #1341) enumerates paths via BFS over a queue of incomplete walks. In simple-paths-only mode each pop must check the path’s vertex set for self-intersection. In non-simple mode the set is irrelevant — the fix gates the rebuild behind simplePathsOnly and switches the queue from LinkedList to ArrayDeque.

Same behavior, fewer cycles per pop. Covered by the existing testCycleBehavior on AllDirectedPathsTest plus a new brute-force oracle suite.

See: AllDirectedPaths.
